【ふるさと納税アプリ用・最新版 JSON作成依頼】

Libraryにある最新資料と、既存のアプリ用データを照合して、アプリへ取り込むためのJSONを作成してください。

■基本ルール 1.
既存データとLibraryの最新資料を比較し、同一資料・同一内容の重複を除外してください。
2.
給与明細・賞与明細・源泉徴収票は、原文に記載されている項目を省略せず、可能な限り全項目を構造化して保存してください。
3. JSONは必ず次の形式で返してください。 {“version”:1,“documents”:[…]} 4.
JSONはアプリが直接読み込むための構造化データです。アプリ側でPDF/OCRの文字列を再解釈して計算しないで済むよう、読み取った値を適切なJSON項目に格納してください。
5.
読み取れない項目は推測して埋めず、nullまたは要確認として扱ってください。
6.
資料にない値を、前年データ・別資料・計算結果から勝手に補完しないでください。
7.
個人名・氏名は読み取らないでください。扶養親族についても氏名をJSONに保存しないでください。

■源泉徴収票の扶養人数
源泉徴収票の「控除対象扶養親族等の数」欄を直接読み取ってください。

以下を必ず独立した項目として保持してください。 -
dependentGeneralCount：一般扶養親族の人数 -
dependentSpecificCount：特定扶養親族の人数 -
specialDependentCount：特定親族特別控除の対象人数 -
specialDependent：特定親族特別控除額

重要： - 個人名から扶養区分を判断しない。 -
dependentChildren等の別情報から扶養区分を推測しない。 -
一般扶養と特定扶養を合計して1項目にしない。 -
特定扶養と特定親族特別控除を同じ項目として扱わない。 -
源泉徴収票の人数欄が読み取れない場合は、推測して0にせず、nullまたは要確認としてください。 -
年分によって制度が存在しない場合は、その制度を無理に適用しないでください。
例：2024年分には特定親族特別控除はありません。

■源泉徴収票と給与・賞与データ
源泉徴収票が存在する年度でも、以下を混同しないでください。 A.
源泉徴収票ベースの実績データ B. 給与・賞与の実績＋不足分の予測データ

AとBは独立して計算できるよう、それぞれの元データを保持してください。
源泉徴収票がない年度は、給与・賞与の実績＋予測を使用できるようにしてください。

■給与・賞与明細
給与明細・賞与明細については、原文の項目を省略せず保存してください。
特に以下を区別してください。 - 支給額・給与 - 課税支給額 -
非課税支給額 - 社会保険料 - 健康保険 - 介護保険 - 厚生年金 - 雇用保険 -
その他の社会保険項目 - 所得税 - 住民税 - その他の控除 -
特別支給・追加支給等 - その他、原文に存在する項目

■源泉徴収票
源泉徴収票については、少なくとも以下を独立項目として保持してください。 -
支払金額 - 給与所得控除後の金額 - 所得控除の額の合計額 - 源泉徴収税額 -
社会保険料等の金額 - 生命保険料の控除額 - 地震保険料の控除額 -
住宅借入金等特別控除の額 - 基礎控除 - 所得金額調整控除 -
一般扶養親族人数 - 特定扶養親族人数 - 特定親族特別控除対象人数 -
特定親族特別控除額 - 配偶者関係の人数・控除額など、原文にある関連項目 -
その他、源泉徴収票原文にある項目

■所得金額調整控除
所得金額調整控除は、手動入力値として作成しないでください。
年分・年収・適用要件からアプリ側で自動計算できるよう、計算に必要な事実データを保存してください。
源泉徴収票に記載された給与所得控除後の金額等については、原文の値をそのまま保存してください。

■手動入力 手動入力値は、元資料のJSONに勝手に埋め込まないでください。
アプリ側で設定する手動入力項目と、資料から読み取った実績値を混同しないでください。

■扶養に関する注意 「特定扶養親族」と「特定親族特別控除」は別制度です。
必ず別々のJSON項目として扱ってください。

例： { “dependentGeneralCount”: 1, “dependentSpecificCount”: 1,
“specialDependentCount”: 0, “specialDependent”: 0 }

この例のように、人数・制度を混ぜずに保持してください。

■最終確認 JSONを返す前に、 - 重複資料がないか - 年度が正しいか -
給与・賞与・源泉徴収票を取り違えていないか -
一般扶養と特定扶養が分離されているか -
特定扶養と特定親族特別控除が分離されているか -
個人名がJSONに入っていないか - 読み取れない値を推測していないか -
手動入力値を勝手に混ぜていないか を確認してください。

完成したJSONだけを、指定形式 {“version”:1,“documents”:[…]}
で返してください。
