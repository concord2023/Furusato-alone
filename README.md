# ふるさと納税 上限管理（Standalone）

Google Driveを使わず、PDFを直接登録する検証用アプリです。ブラウザのIndexedDBに解析済みデータと処理ログを保存し、次回以降は保存済みデータから計算します。

## 今回の検証済み範囲
- 2025年1〜11月給与明細11件を検証データとして保持
- PDFのテキスト抽出→項目解析を検証
- 課税対象額、支給合計、非課税、雇用保険、健康保険、介護、年金、控除合計、加算、手取りを個別保存
- 11か月の社会保険料合計が 1,050,666円になることを検証
- 同じPDFを再登録してもSHA-256で重複登録しない
- PDF抽出情報（ページ数、文字数、文字項目数）を保存
- DB保存ログをIndexedDBに保存し、TXTで書き出し可能
- 手動入力は0
- 2025年源泉徴収票は予測計算に使用しない

## 検証順序
1. 2025年1〜11月給与明細を実績として登録
2. 手動入力は0
3. 源泉徴収票は計算に使用しない
4. 12月給与を予測して上限を仮試算
5. 12月給与・賞与がそろったら予測を実績へ置換
6. 最後に源泉徴収票を追加し、最終値との比較

## 予測について
12月給与は1〜11月の課税対象額の単純平均を初期予測として使用します。賞与が未登録の場合は推測で補完しません。

令和7年分の給与所得控除・基礎控除のルールを反映しています。ただし、予測段階では年末時点の扶養・各種控除等が確定していないため、表示する寄附上限は「仮試算」です。最終値として扱いません。

## PDF処理
PDF.jsでテキスト抽出を先に試します。抽出文字数・テキスト項目数・ページ数・解析結果をDBとデバッグログに残します。抽出文字が極端に少ないPDFは「抽出不足」として止め、原因をログで確認できる構造です。

## 注意
- 現在は検証用の単独版です。
- PDF自体のバイナリはDBに保存せず、ファイル名・サイズ・抽出テキスト・解析結果・抽出メタデータを保存します。
- 源泉徴収票が登録された後の「最終値への切替」は次ステージで実装・検証します。
