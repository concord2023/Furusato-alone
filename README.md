# ふるさと納税 上限管理アプリ

## 今回のデバッグ修正
- 資料種別をファイル名・文書名から再判定：`Chinginmeisai`=給与、`Bonus`=賞与、`Gensen`/`Genseb`=源泉徴収票。
- 既存DBの `unknown` / 旧 `type` 形式を起動時に正規化。
- 2024年12月の給与と賞与を別レコードとして保持。
- 年度別一覧を「給与」「賞与」「源泉徴収票」「その他・未分類」に分離。
- 各資料について読み取った項目を表形式で展開し、保存された原文テキストも確認可能。
- 持株会・持株補助を支給項目・追加支給・控除項目から確認できるように修正。
- 手動入力は保存ボタンでDBへ保存し、保存完了メッセージと計算反映を表示。
- 生命保険料控除は一般生命・個人年金・介護医療の内訳と合計120,000円上限を表示。
- 本人の国民年金と娘の国民年金を別入力し、娘分の控除対象への算入を明示。
- 源泉徴収票は予測計算には使用せず、実績後の比較用に保存。

## 2024年資料で確認した内容
Libraryで作成済みの2024年差分JSONは15資料：給与12、賞与2、源泉徴収票1。資料名からの分類テストではunknown 0件、重複ID 0件。

## 公開用の注意
個人の給与・賞与・源泉徴収票データはこの公開アプリのファイルには含めません。実データは端末内IndexedDBへ保存し、ChatGPTから受け取ったJSONをアプリ画面から反映します。


## 2026-09-28 追加デバッグ
- 既存DBに残っていた古い `needsReview=true` をそのまま引き継がず、給与の必須項目（年度・月・課税対象額・支給合計）から再判定するよう修正。
- 2024年12月給与の原資料には所得税の独立項目がないため、所得税欠落を理由に「要確認」にしない。
- 手動入力の新生命保険料について、2024/2025年にも通常の生命保険料控除計算が適用されるよう修正。従来は `newLife` が2026年の23歳未満特例分岐に入らない年度で0円になっていた。
- 手動入力保存後は、その入力年度を上限計算年度にも自動選択し、反映先を明確化。
- 上限試算画面から「12月給与」単独表示を削除し、年間給与（実績＋予測）と1〜12月の実績/予測内訳を表示。


## 2026-10-03 計算基準の修正
- 源泉徴収票がある年度でも、源泉徴収票をすべての項目で自動的に「正」としない構造へ変更。
- 支払金額、社会保険料、生命保険料控除、地震・旧長期損害、iDeCo、本人の国民年金、娘の国民年金、扶養・特定親族等、所得金額調整控除について、各項目ごとに「源泉徴収票」「給与・賞与ベース」のチェックボックスを表示。
- 両方の金額を画面上で比較でき、実際の計算には選択した側だけを使用。
- 源泉徴収票がない年度は「給与・賞与ベース」を自動選択。
- 手動入力は、源泉徴収票へ単純に加算するのではなく、「給与・賞与ベース」を構成するための値として反映。
- 確定申告などで源泉徴収票の内容と最終申告内容が変わる場合、該当項目だけ給与・賞与ベースへ切り替えて手動入力を反映できる。
- 旧 `useManual` 設定が残っているバックアップも読み込み時に新しい項目別基準へ移行する。
