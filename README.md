# ふるさと納税 上限管理アプリ

## 今回の修正・検証
- 資料種別をファイル名・文書名から再判定：`Chinginmeisai`=給与、`Bonus`=賞与、`Gensen`/`Genseb`=源泉徴収票。
- 既存DBの `unknown` / 旧 `type` 形式を起動時に正規化。
- 同一年度・同一月でも給与と賞与は別レコードとして保持。
- 年度別一覧を「給与」「賞与」「源泉徴収票」「その他・未分類」に分離。
- 各資料について読み取った項目を表形式で展開し、保存された原文テキストも確認可能。
- 持株会・持株補助を支給項目・追加支給・控除項目から確認できるように修正。
- 手動入力は保存ボタンでDBへ保存し、保存完了メッセージと計算反映を表示。
- 生命保険料控除は一般生命・個人年金・介護医療の内訳と合計120,000円上限を表示。
- 本人の国民年金と娘の国民年金を別入力し、娘分の控除対象への算入を明示。
- 年度ごとに計算根拠を自動判定：源泉徴収票が存在し必要な年間値を取得できる年度は源泉徴収票の実績を優先し、給与・賞与は内訳・検証用として保持。源泉徴収票がない年度は給与・賞与の実績＋不足分の予測で計算。

## 公開用の注意
個人の給与・賞与・源泉徴収票データはこの公開アプリのファイルには含めません。実データは端末内IndexedDBへ保存し、ChatGPTから受け取ったJSONをアプリ画面から反映します。

## 年度別の計算優先順位
- 年度を固定せず、保存されている全年度を同じロジックで処理。
- ①源泉徴収票あり：源泉徴収票の年間実績を優先。給与・賞与は内訳・検証用。
- ②源泉徴収票なし：給与・賞与の実績を使用。
- ③年度途中：取得済み月は実績、未取得月だけ予測。取得済み実績を予測で上書きしない。
- ④賞与も実績優先。不足分を前年の対応月等から予測する場合は、根拠年度・月を表示。
- 源泉徴収票が後から追加された場合、その年度は自動的に源泉徴収票優先へ切り替える。

- 通常画面から内部ログの表示・出力を削除。内部処理用ログは通常UIに表示しない。
- 内部計算値の単独表示をやめ、上限概算の計算内訳を①〜⑪で明示。
- iDeCoを国民年金と別項目で表示。国民年金は本人・娘を分けて表示し、合計関係を明示。
- 生命保険料控除は一般生命・介護医療・個人年金を①〜③で分け、支払額→計算式→区分上限→3区分合計120,000円上限の順で表示。
- 給与・賞与は【実績】／【予測】、手動控除は【入力】、源泉徴収票は存在する年度では【実績・計算優先】として明示。
- 未取得月の給与・社会保険料は、4〜9月に実績がある場合は4〜9月実績平均を基準に10〜12月を予測。4〜9月の一部しか取得できない場合は取得済み4〜9月の平均を使用。
